# 把销冠助手的同步后端搬到 EdgeOne

这份文档假设你「有 EdgeOne 账号但没在 EdgeOne 上部署过 Node 函数」，按步骤走就行。

---

## 先说清楚：它能替掉什么、替不掉什么

| 场景 | EdgeOne 能不能干 | 说明 |
|---|---|---|
| 托管网页本身 | **能，但没必要** | 本机双击 `index.html` 就能用，也能用随项目自带的 `node server.js` 自己托管。托管到 EdgeOne 只多一个「换台电脑也能打开页面」的便利 |
| 直接跑 `server.js` | **不能** | EdgeOne 的 Cloud Functions 没有持久文件系统，`server.js` 往 `data/` 里写的那个 JSON 文件，函数重启一次就没了 |
| **做同步后端** | **能，而且是正解** | 用 Node Functions 收请求 + Blob 存数据。免运维、有免费额度、不用自己养服务器 |

所以这份文档只做一件事：**把同步后端搬上去**。前端继续用你现在的用法（双击本地文件，或自己起服务器），只是在「设置 → 同步地址」里把地址换成 EdgeOne 给你的域名。

---

## 为什么选 Blob，不选 KV

EdgeOne 提供两种存储，选错了会**丢数据**，所以这里必须讲明白。

同步这件事的本质是「读 → 合并 → 写」。

- **KV 是最终一致的**（最长 60 秒陈旧读），而且**没有 CAS**（比较并交换）。
  手机读到 60 秒前的旧数据、合并、写回 —— 电脑刚推上去的客户记录就被覆盖了。
- **Blob 支持强一致读**（`consistency: "strong"`），写完立刻能读到最新值。

光有强一致还不够。「读 → 合并 → 写」中间那个窗口依然存在竞态：
手机和电脑同时读到 v1，各自合并后写回，后写的覆盖先写的。

所以本适配器**不让多台设备抢同一把钥匙**：

```
sync/<令牌空间>/<设备ID>.json     ← 每台设备只写自己这一个文件
```

读取时把该空间下**所有设备**的文件全部 merge 起来再返回。谁也覆盖不了谁。
而且合并规则是「同一条记录按 `updatedAt` 取新的」，它满足交换律和结合律，
所以哪怕某一次读到了别人稍微陈旧的副本，多同步几次之后所有设备依然会收敛到同一份结果。

代价：空间占用随设备数线性增长。个人通常 1~3 台设备，免费额度 1GB，
几千条客户和跟进记录不过几百 KB，完全用不完。

## 部署步骤

### 1. 准备这个目录

把这个 `deploy/edgeone` 目录**整个拷贝**成一个新项目（比如叫 `sales-copilot-sync`）。
它就是一个最小的 EdgeOne 项目骨架：

```
sales-copilot-sync/
├── package.json
├── prepare.js
└── cloud-functions/
    ├── _shared/
    │   └── sync-core.js        ← 由 prepare.js 生成，别手改
    └── api/
        ├── sync.js             ← 线上路由 /api/sync
        └── health.js           ← 线上路由 /api/health
```

然后跑一次准备脚本：

```bash
node prepare.js
```

看到 `✓ 已生成 cloud-functions/_shared/sync-core.js` 就成了。
**每次升级销冠助手之后，都要重新跑一次这个脚本**再部署，否则新版本的合并逻辑不会生效。

> 这个脚本是把主项目的 `sync-core.js`（合并算法）复制过来。
> 之所以不在 EdgeOne 里直接引用上层目录的文件：EdgeOne 构建时只保证
> 把 `cloud-functions` 目录内的模块带进产物，跨出去的路径能不能带上全看运气。

### 2. 装依赖

```bash
npm install
```

只会装一个包：`@edgeone/pages-blob`。

### 3. 推到 Git

EdgeOne Pages 从 Git 仓库构建。GitHub / GitLab / Gitee 都行，推上去。

### 4. 在 EdgeOne 控制台创建项目

1. 进入 EdgeOne 控制台 → **Pages**
2. 新建项目 → 绑定刚才那个仓库
3. 构建配置：
   - **框架预设**：选 `其他` 或 `无`
   - **输出目录**：留空（本项目没有前端产物）
   - **安装命令**：`npm install`
   - **构建命令**：留空
4. 点部署，等它跑完

### 5. 配置环境变量（可选但强烈建议）

部署完成后，在项目 **设置 → 环境变量** 里加：

| 变量 | 建议值 | 说明 |
|---|---|---|
| `SYNC_TOKEN` | 你自己想一个长一点的串 | **填了就进入「专属模式」：只认这一个令牌**。个人自用强烈建议填，别人就算拿到你的同步地址也进不来 |
| `BLOB_STORE` | `sales-copilot` | Blob 命名空间名字，一般不用改 |
| `MAX_DEVICES` | `20` | 单个令牌下最多允许几台设备。超了会报 413，防止客户端 bug 把存储写爆 |

改完环境变量要**重新部署一次**才生效。

### 6. 先验证后端活着

浏览器打开：

```
https://你的域名/api/health
```

应该看到类似：

```json
{
  "ok": true,
  "app": "sales-copilot",
  "mode": "专属模式（单令牌）",
  "store": "sales-copilot",
  "stores": ["sales-copilot"],
  "blobReady": true,
  "hint": "带上 X-Sync-Token 头可以看到你这个令牌下的数据条数"
}
```

如果 `ok` 是 `false`，`error` 字段会告诉你为什么 —— 最常见的就是 Blob 命名空间没建起来，
手动访问一次 `/api/sync` 触发一次写入即可（`getStore` 首次调用会自动建命名空间）。

### 7. 在 App 里填地址

打开销冠助手 → **设置 → 云同步**：

- **同步地址**：`https://你的域名/api/sync`
- **同步令牌**：你设的 `SYNC_TOKEN`，或者任意 ≥8 位的串（没设 `SYNC_TOKEN` 时）

然后点「立即同步」。手机上填一样的地址，两台设备就通了。

## 和本地 server.js 的关系

两边实现的是**同一套协议**，前端不需要任何改动，换个 URL 就切换了：

| | 本地 `node server.js` | EdgeOne 本适配器 |
|---|---|---|
| 接口 | `GET /api/sync`、`PUT /api/sync` | 完全相同 |
| 鉴权 | `X-Sync-Token` / `Bearer` / `?token=` | 完全相同 |
| 合并算法 | `sync-core.js` | 同一个文件生成的副本 |
| 存储 | 本地 `data/*.json` | Blob |
| 并发安全 | 单进程，天然安全 | 每台设备独立文件 |
| 备份 | 每次覆盖前留档，保留最近 10 份 | 无自动备份 |

想两边都用也行：电脑上跑 `node server.js`，手机上指 EdgeOne ——
但因为是两个独立的存储，数据不会互通。选一个长期用就好。

## 故障排查

| 现象 | 原因 / 怎么办 |
|---|---|
| `401 令牌无效` | 设了 `SYNC_TOKEN` 就必须用完全相同的串，注意别带空格；没设的话令牌要 ≥8 位 |
| 浏览器报 CORS 错误 | 本适配器已经对所有响应加了 CORS 头。如果还报，检查是不是请求被 EdgeOne 的 WAF 拦了 |
| `413 设备数已达上限` | 同一令牌下有太多设备 ID。通常是客户端每次刷新都生成了新 ID，去 Blob 控制台把 `sync/<空间>/` 下多余的文件删掉 |
| 同步成功但另一台看不到 | 先访问 `/api/health` 带上 `X-Sync-Token` 看 `devices` 是不是 ≥2。只有 1 说明第二台根本没推上来 |
| 数据对不上 / 少了几条 | 确认两台设备跑的是同一版本的销冠助手，然后各点一次「立即同步」让它收敛 |
| 改了 `sync-core.js` 没生效 | 忘了跑 `node prepare.js` |

## 已知限制

- **没有自动备份**：本地 `server.js` 每次覆盖前会留档，Blob 版本没有。重要数据请定期用 App 里的「导出 JSON」存一份。
- **强一致读比最终一致慢一点**：同步宁可慢几十毫秒也不能读到旧数据，所以整个 store 都用了 `strong`。数据量大的话可以考虑只在 PUT 时用强一致。
- **免费额度 1GB**：个人用不完。真到瓶颈了，先在 App 里用「压缩数据」清掉墓碑记录。

## 顺带：想把网页也托管上去？

可以，但意义不大。如果确实想：

1. 在 `deploy/edgeone` 下建 `public/` 目录
2. 把 `index.html`、`styles.css`、所有 `.js`、`manifest.json`、图标拷进去
3. EdgeOne 构建配置里把**输出目录**填 `public`

注意：网页一旦托管到线上域名，而同步地址填的还是另一个域，就会走跨域 ——
本适配器已经处理了 CORS，所以能正常工作。
