# 销冠助手

**一个跑在浏览器里的个人销售作战台。零依赖、零构建、断网可用，数据只存在你自己的设备上。**

没有账号体系、没有服务器、没有月费。打开网页就能用，关掉网页数据还在。
配了 Supabase 之后可以多设备同步、多人协作，但**不配也能完整使用**。

## 为什么是它

销售工具的通病是：**记起来太麻烦，所以用两天就废了。**

CRM 让你填十几个字段才存得进一条跟进，结果就是晚上补记、凭印象填、最后数据全是假的。
这个工具反过来做——所有设计围绕一件事：**让你在客户楼下等电梯的 30 秒里，把刚发生的事记完。**

| | 常见 CRM | 销冠助手 |
|---|---|---|
| 记一条跟进 | 打开表单、选客户、选类型、填内容、提交 | 一句话，回车 |
| 装在哪 | 公司服务器 / SaaS | 一个 HTML 文件，或者一个网址 |
| 断网 | 用不了 | 照常用，联网后自动补同步 |
| 数据归谁 | 厂商的库 | 你浏览器的 localStorage，谁也拿不走 |
| 成本 | 按人头按月 | 0 |

## 快速开始

### 用法一：打包成单文件版（推荐先试这个）

```bash
node build.js
```

会生成 `销冠助手-单文件版.html`——整个应用就这一个文件，双击用浏览器打开就能用，
可以丢进网盘、发到微信、存到手机里。**适合先试两天看看顺不顺手。**

（这个文件是构建产物，不放在仓库里，所以 clone 下来要自己跑一次上面的命令。
需要 Node，但除了 Node 本身不需要装任何依赖。）

### 用法二：本地跑源码

```bash
git clone <你的仓库地址>
cd sales-copilot
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000
```

任何静态服务器都行（`npx serve`、`php -S`、Nginx 均可）。
**不能直接双击 `index.html`**——浏览器不允许 `file://` 加载多文件模块。

### 用法三：部署成网址

见 [部署到线上](#部署到线上)，支持 Cloudflare Pages、Vercel 或任意静态托管。
部署后可以装到手机桌面，像 App 一样打开。

> 第一次打开会有一批示例数据（几个客户、商机、跟进记录），方便你直接看到各页面长什么样。
> 在「设置」里清空即可——**清空后不会再自动出现**。

## 功能模块

九个模块，都在底部页签里。

### 战情台（首页）

打开就看到的作战面板：本月回款进度、目标完成率、今天该联系谁、哪几单有风险、
最近七天记了多少条跟进。不需要点进任何子页面就能掌握全局。

### 客户库

客户分级（A 重点 / B 常规 / C 观察）、状态、联系人、行业、标签。
点进详情页能看到这个客户的全部跟进时间线、关联商机、**以及此刻该对他说什么**。

### 商机看板

七个阶段拖拽推进，每个阶段带成交概率：

| 阶段 | 线索 | 接触 | 方案 | 报价 | 谈判 | 赢单 |
|---|---|---|---|---|---|---|
| 默认概率 | 10% | 25% | 45% | 65% | 80% | 100% |

（另有「输单」不在看板上。）看板按阶段分列，卡片显示金额、预计成交日、健康度圆点。

### 跟进日志

所有跟进按时间倒序，可按客户、类型筛选。类型包括电话、微信、拜访、会议、邮件。

### 话术库

内置 **48 条**实战话术，9 大类。支持语义搜索、按客户意图筛选、一键复制。
赢单或输单时可以一键把这一仗沉淀成自己的话术。详见 [话术库](#话术库)。

### 周报

自动汇总本周新增客户、推进的商机、跟进次数、下周待办，可以直接复制发出去。

### AI 助手

接了大模型才能用，不接不影响其余功能。可以做销售建议、话术生成、AI 陪练对打。
详见 [AI 助手](#ai-助手)。

### 团队看板

**只有管理员看得到。** 展示全队每个人的在谈金额、商机数、赢单数。
刻意不显示客户具体名字——团队看板是看进度的，不是让老板扒下属客户名单的。

### 设置

个人信息、月度目标、提成比例、AI 配置、云同步、数据导入导出、健康度灵敏度。

## 一句话录入

这是整个工具的核心。在任何页面顶部都有输入框，一句话回车即可。

```
今天去了王总那儿，聊了报价，他说下周三再联系
```

系统自动拆成：

| 字段 | 解析结果 |
|---|---|
| 客户 | 王总（模糊匹配已有客户） |
| 类型 | 拜访（「去了」「那儿」识别为拜访） |
| 内容 | 聊了报价 |
| 下次跟进 | 下周三（识别到「下次…联系」才设置） |

支持的类型词：电话、拜访、会议、微信、邮件。

时间能听懂「今天」「明天」「后天」「下周三」「月底」「3 天后」「下周」这类说法。

> **一条刻意的设计**：只有出现明确的「下次 / 回头 / 再联系 / 过几天」这类词，
> 才会设置下次跟进时间。「他说下周三报价」是**对方**的时间点，
> 不等于你下次要联系他——这种语义分不清，宁可不设。误设比不设烦人得多。

## 商机健康度

每个商机算一个 0–100 分，扣分的四个信号：

| 信号 | 最多扣 | 判定依据 |
|---|---|---|
| 沉默 | 35 | 多久没跟进，对比**你自己**平时的节奏 |
| 阶段停滞 | 30 | 卡在当前阶段多久，对比你历史上走完这阶段要多久 |
| 临期 / 过期 | 35 | 预计成交日只剩几天，或已经过了 |
| 无实质推进 | 10 | 近 30 天既没换阶段、也没记跟进 |

扣分时**同时给出下一步动作建议**，并且是一句话能执行的那种
（不是「请加强跟进」，而是「给李经理打个电话，问一句报价这块卡在哪」）。

### 基准是学出来的，不是写死的

初始值按客户等级 A/B/C 给一套兜底天数，但系统会从你自己的历史数据里学：

- **跟进节奏**：这个客户平时多少天联系一次 → 超过这个节奏的 1.6 倍才算异常
- **阶段耗时**：你走完「方案」平均要几天 → 拿它当基准

所以**用得越久，判断越准**。没有历史数据时退化为等级兜底，并在文案里说明「这是估算的」。

### 三个刻意的克制

1. **新建 3 天内不评分**——刚录进去的单子没数据，硬算必然误伤
2. **可以忽略**——你说过「这条我知道」，就不再念（默认忽略 7 天）
3. **灵敏度可调**——设置里 0.4（严格）到 2.5（宽松），默认 1

## 回款预测与目标倒推

### 本月回款预测

不用「所有在谈金额加起来」这种虚的算法，而是：

```
每个商机的金额 × 所在阶段的成交概率，逐单累加
```

阶段概率也不是写死的——**从你自己的历史赢单记录里算出来**。
你历史上从「报价」走到「赢单」的比例是多少，就用多少。没有历史数据时才用默认概率。

### 目标倒推

告诉你这个月**还差多少、还来不来得及**：

- 已回款 / 目标
- 按当前在谈金额加权后，预计能完成多少
- 差额是多少
- 按你平均客单价折算，还差几单
- 按你平均成交周期，现在签的单还赶不赶得上本月

## 话术库

### 内置 48 条，9 大类

| 分类 | 条数 | 覆盖场景 |
|---|---|---|
| 异议处理 | 16 | 太贵了、比别家贵一倍、反复砍价、没预算、再比较比较…… |
| 催单推进 | 6 | 催决策、催流程、催回款 |
| 开场破冰 | 5 | 陌生拜访、转介绍、展会后跟进 |
| 需求挖掘 | 5 | 挖痛点、挖决策链、挖预算 |
| 售后维护 | 5 | 交付后回访、处理不满 |
| 谈判博弈 | 4 | 让步节奏、条件交换 |
| 方案报价 | 3 | 报价铺垫、价值锚定 |
| 复盘沉淀 | 2 | 输单总结、赢单归因 |
| 交付履约 | 2 | 交付承诺、验收推进 |

### 搜索能听懂意图

不是关键词匹配。输入「客户嫌贵怎么说」，它按**语义 + 意图标签**排序，
能找到标题里没有「贵」字但讲的是同一件事的话术。

### 战后沉淀：把打过的一仗变成资产

赢单或输单时，系统会从这笔商机的跟进记录里提取关键信息，
生成一条属于你自己的话术候选，你确认后入库。

> 一万条别人的话术，不如你自己攒的二十条。
> 因为只有你知道你的行业、你的产品、你的客户会怎么怼你。

### ⚠ 关于跨域：有 5 家浏览器连不上

这个工具跑在浏览器里，请求是浏览器直接发出的。
实测 32 家中，有 **5 家的接口不返回跨域许可**，浏览器直连一定被拦截：

> 豆包（火山方舟）、讯飞星火、Groq、Cerebras、SambaNova

这几家在下拉框里带 **⚠ 浏览器直连会被拦** 标记。
选中时会明确告诉你：要么换一家，要么自己搭一层代理转发。

**不要在这几家上浪费时间试 Key。** 接口本身是通的（服务端调用没问题），
只是不允许浏览器直接调。国内这几家都能直连：DeepSeek、智谱、通义、千帆、混元、硅基流动。

本机自建的（Ollama / LM Studio）也要额外开跨域：
Ollama 要设 `OLLAMA_ORIGINS=*` 后重启，LM Studio 在设置里勾「允许跨域」。

### 地址填错会自己修

填的地址少了一截（比如智谱少了 `/v4`），点「拉取」会拿到 404。
这时程序会**自动把常见的几种写法都试一遍**（`/v1`、`/v4`、`/api/v1`、`/api/paas/v4`、
`/openai/v1`、`/compatible-mode/v1`），试出来就直接帮你改好并重新拉取，一步都不用你动。

试不出来也会明说试过哪些、建议你手动填模型名绕过——不会只丢一句 `Failed to fetch`。

## 多人与团队

一个人用不用管这块。多人用可以：每人一个账号，**各自的客户和商机互相看不见**，
管理员能看到全队的进度汇总。

### 角色

| 角色 | 能看到 | 能做什么 |
|---|---|---|
| 拥有者 / 管理员 | 自己的全部数据 + 团队看板 | 发邀请码、移出成员、看全队进度 |
| 普通成员 | 只有自己的数据 | 加入/退出团队 |

**隔离是在数据库层做的（Postgres RLS），不是在前端藏一藏。**
普通成员就算直接改前端代码、直接调接口，也拿不到别人的记录。

### 搭建步骤

1. 注册 Supabase（免费），建一个项目
2. 把仓库里的 `supabase.sql` 整段粘进 SQL Editor 执行一次
3. 应用「设置」里填 Project URL 和 anon key
4. 注册账号，第一个注册的人自动成为拥有者
5. 在「团队」页生成邀请码，发给同事

数据库表：`profiles`、`records`、`teams`、`team_scripts`、`user_settings`。

## 云同步

### 本地优先（Local-first）

**所有数据先写浏览器 localStorage，再考虑同步。** 断网、服务器挂了、没配置同步——
都不影响你记录和查看。联网后自动补上。

同步以记录为单位、按 `updatedAt` 判定谁新，删除走「墓碑」机制（标记删除而不是真删），
避免一台设备删了、另一台设备又把它同步回来。

### 三种路线

| 路线 | 适合 | 说明 |
|---|---|---|
| **不配置** | 一个人用 | 数据只在本地。换设备用导出/导入 JSON |
| **Supabase** | 长期用、多人用 | 免费额度足够个人和小团队，也是团队功能的前提 |
| **自建服务器** | 有自己的机器 | 仓库里的 `server.js`，支持 Docker 和 systemd |

> 部署在 Cloudflare Pages / Vercel 这类**纯静态托管**上时，`server.js` 是跑不起来的
> （平台不给跑 Node 进程）。这种情况下云同步请走 Supabase 那条路。

### 离线时会怎么说

网络不通时不会只丢一句 `Failed to fetch`，而是告诉你：

> 连不上同步服务：现在是离线状态。**本机的数据一条不少，该记的照记，联网后会自动同步。**

销售在外面跑，地铁里没信号是常态。这时候必须让你知道记录没丢，不然你会反复重试。

## 部署到线上

> ⚠️ **只部署 `public/` 目录，不要部署整个仓库根目录。**
> 根目录里有 `data/`——那是你的真实客户资料。而静态托管的特点是
> **传上去的每个文件都是公开可下载的**，整个目录一传等于把客户名单挂在网上。
> 构建脚本已经帮你隔离好了。

### 构建

```bash
node build.js --pages     # 生成 public/（用于部署）
node build.js             # 生成单文件版（用于本地/分享）
```

### Cloudflare Pages

```bash
npm i -g wrangler
node build.js --pages
npx wrangler pages deploy public
```

或在控制台创建项目时填：构建命令空着，输出目录 `public`。

缓存规则写在 `deploy/_headers`，构建时会复制到 `public/`。

### Vercel

```bash
node build.js --pages
npx vercel --prebuilt --prod
```

`vercel.json` 已经配好了各类型文件的缓存头。

### 其他静态托管

把 `public/` 整个目录上传即可（GitHub Pages、对象存储、Nginx 都行）。

### PWA 安装到手机

部署后用手机浏览器打开，通过「添加到主屏幕」安装。
之后可以离线打开、全屏运行、有独立图标。

## 数据与隐私

| 问题 | 答案 |
|---|---|
| 数据存在哪 | 浏览器的 localStorage，就在你自己的设备上 |
| 会上传到我的服务器吗 | 没有「我的服务器」——项目不含后端，除非你自己配 |
| 不配同步能同步吗 | 不能，但能用导出/导入 JSON 手动搬 |
| `data/` 目录是什么 | 本地调试时的数据快照，**已在 `.gitignore` 里，永远不进版本库** |
| 换浏览器/清缓存 | 数据会没。这也是为什么建议开云同步或定期导出 |

`data/` 里是真实的客户姓名、电话、微信。就算仓库设成私有也一样——
私有仓库照样会被误共享、误导出、误截图。

```
├── team.js             团队看板与成员管理
├── sync.js             云同步
├── sync-core.js        同步核心逻辑（前后端共用）
├── notify.js           提醒
│
├── sw.js               Service Worker（离线缓存）

├── public/             构建产物（已在 .gitignore 中）
└── data/               本地数据快照（已在 .gitignore 中）
```

**技术上的刻意选择**：原生 HTML / CSS / JavaScript，没有框架、没有构建工具、
没有 npm 运行时依赖、没有 CDN 外链。整个应用由浏览器直接执行源码。

好处是：不会有依赖过期、不会有构建失败、断网能用、十年后打开还是能跑。
代价是代码量大——这点代价换长期可维护性，值得。

## 二次开发提示

- **加一个页面**：在 `views.js` 里加渲染函数，`ui.js` 里加 `data-action` 处理，
  `index.html` 里加页签
- **加一个数据字段**：改 `store.js` 的 `emptyState()`，并在 `migrate()` 里补兼容
- **改 AI 服务商预设**：`ai.js` 顶部的 `PROVIDERS`
- **改健康度算法**：`health.js`，四个信号各自独立，改一个不影响其他
- **改缓存策略**：`sw.js` 的 `FILES` 清单由 `build.js` 自动生成，
  不要手改（手改会在下次构建时被覆盖）

改完记得跑构建产出新的 `public/`：

```bash
node build.js --pages
```
